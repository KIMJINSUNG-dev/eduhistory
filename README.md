# 교육 수강내역 조회 시스템

교육 수강내역을 검색하고 검색 결과를 파일로 내려받는 웹 애플리케이션입니다.
화면설계서의 요구사항에 따라 검색어 · 교육일 · 수강상태 조건을 조합한 조회와,
조회 결과 기준의 다운로드 기능을 구현했습니다.

## 기술 스택

### 백엔드

| 구분 | 내용 |
| --- | --- |
| 언어 | Java 17 |
| 프레임워크 | Spring Boot 4.1.1 |
| 빌드 도구 | Maven |
| DB 접근 | MyBatis (mybatis-spring-boot-starter 4.1.0) |
| DB | MySQL 8.0 |
| 라이브러리 | Apache Commons CSV 1.14.1 |

### 프론트엔드

| 구분 | 내용 |
| --- | --- |
| 언어 | TypeScript 6.0 |
| 라이브러리 | React 19.2 |
| 빌드 도구 | Vite 8.3 |
| 실행 환경 | Node.js 24.14.0 / npm 11.9.0 |

### 스택 선정 이유

- 공공기관 SI/SM 환경을 고려해 전자정부 표준프레임워크와 기반이 같은 **Spring** 계열을 선택했습니다.
- DB 접근은 전자정부 표준프레임워크의 표준 방식인 **MyBatis**를 사용했습니다.
  검색 조건이 선택적으로 결합되는 요구사항이라 동적 SQL(`<where>`, `<if>`)이 적합했습니다.
- 패키지 구조와 클래스 네이밍(`Service` / `ServiceImpl` / `Mapper` / `VO` / `~ApiController`)도
  전자정부 표준프레임워크 관례를 따랐습니다.
- Spring Boot는 오픈소스 지원이 유지되는 4.1.x 버전을 사용했습니다.

## 실행 방법

### 사전 준비

- JDK 17 이상
- MySQL 8.0 이상 (실행 중인 상태)
- Node.js 20 이상 (개발 환경 기준 24.14.0)

별도의 DB 생성이나 데이터 적재 작업은 필요하지 않습니다.
애플리케이션 기동 시 데이터베이스 · 테이블 생성과 CSV 데이터 적재(292건)가 자동으로 수행됩니다.

### 1. 백엔드 실행

DB 접속 계정을 환경변수(`DB_USERNAME`, `DB_PASSWORD`)로 지정한 뒤 실행합니다.

**Windows (PowerShell)**

```powershell
cd backend
$env:DB_USERNAME="root"
$env:DB_PASSWORD="MySQL 비밀번호"
.\mvnw.cmd spring-boot:run
```

**Windows (명령 프롬프트)**

```cmd
cd backend
set DB_USERNAME=root
set DB_PASSWORD=MySQL 비밀번호
mvnw.cmd spring-boot:run
```

**macOS / Linux**

```bash
cd backend
DB_USERNAME=root DB_PASSWORD='MySQL 비밀번호' ./mvnw spring-boot:run
```

IDE에서 실행하는 경우 실행 구성의 환경변수 항목에 동일하게 등록하면 됩니다.

- 기본 포트: `8080`
- 기동 로그에 `데이터 292건 적재 완료`가 출력되면 정상입니다.
  두 번째 실행부터는 `DB에 데이터가 이미 존재합니다. 데이터 적재 작업을 건너뜁니다.`가 출력됩니다.
- 기동 중 `Access denied for user 'root'@'localhost'` 오류가 발생하면
  환경변수가 전달되지 않은 경우이므로, 위 명령을 같은 터미널에서 순서대로 실행해 주세요.

### 2. 프론트엔드 실행

```bash
cd frontend
npm install
npm run dev
```

브라우저에서 `http://localhost:5173` 으로 접속합니다.
개발 서버가 `/api` 요청을 `http://localhost:8080` 으로 전달하도록 프록시를 설정해 두었습니다.

## API

### 목록 조회

```
GET /api/edu-histories
```

| 파라미터 | 값 | 설명 |
| --- | --- | --- |
| `searchType` | `all` / `course` / `institution` | 검색 구분 (미지정 시 `all`) |
| `keyword` | 문자열 | 검색어 (미지정 시 조건 미적용) |
| `startDate` | `YYYY-MM-DD` | 검색 시작일 |
| `endDate` | `YYYY-MM-DD` | 검색 종료일 |
| `status` | `수료` / `수강` / `미수료` | 수강상태 (미지정 시 전체) |

응답

```json
{
  "totalCount": 292,
  "list": [
    {
      "id": 1,
      "traineeName": "교육자 1",
      "eduStartDate": "2024-12-02",
      "eduEndDate": "2024-12-06",
      "courseName": "2023년 본사 산업안전 관리감독자 교육(1차)",
      "institutionName": "대한산업안전협회",
      "courseStatus": "수료"
    }
  ]
}
```

검색 조건이 올바르지 않은 경우 `400 Bad Request`와 함께 안내 메시지를 반환합니다.

```json
{ "message": "교육 시작일과 교육 종료일을 모두 입력해 주세요." }
```

### 다운로드

```
GET /api/edu-histories/download
```

목록 조회와 동일한 파라미터를 사용하며, 조회 결과를 CSV 파일로 반환합니다.

## 구현 범위

### 검색어 검색

- 검색 구분은 전체 / 과정명 / 교육기관이며 기본값은 전체입니다.
- 입력한 검색어를 포함하는 항목을 조회하고, 전체는 과정명 또는 교육기관 기준으로 조회합니다.
- 검색어가 비어 있으면 해당 조건을 적용하지 않습니다.
- 대소문자는 구분하지 않습니다. 일반적인 검색 기능의 동작 방식을 따랐으며,
  DB 설정에 의존하지 않도록 SQL에서 `LOWER()`로 명시적으로 처리했습니다.

### 교육일 검색

- 교육기간과 검색기간이 하루라도 겹치면 조회합니다.
  (`교육시작일 <= 검색종료일 AND 교육종료일 >= 검색시작일`)
- 경계일만 겹치는 경우와 검색기간이 교육기간을 포함하는 경우 모두 조회됩니다.
- 두 날짜를 모두 입력하지 않으면 기간 조건을 적용하지 않습니다.
- 아래의 경우 안내 메시지를 반환합니다.
  - 시작일과 종료일 중 한쪽만 입력한 경우
  - 존재하지 않는 날짜를 입력한 경우
  - 시작일이 종료일보다 늦은 경우

### 수강상태 검색

- 전체 / 수료 / 수강 / 미수료 중 선택하며 기본값은 전체입니다.
- 제공 데이터 기준 수료 245건, 수강 47건이며 미수료는 0건입니다.
  데이터에 존재하지 않는 값이지만 요구사항에 따라 선택 항목으로 제공합니다.

### 복합 검색

- 검색어 · 교육일 · 수강상태 조건을 AND로 결합합니다.
- 조회 후에도 검색 구분, 검색어, 두 날짜, 수강상태의 입력값과 선택값을 그대로 유지합니다.

### 목록 표시

- 최초 진입 시 전체 내역을 조회합니다.
- 검색 결과 건수를 목록 상단에 표시합니다.
- 결과가 없으면 "검색 결과가 없습니다."를 표시합니다.
- 페이지네이션 없이 전체 결과를 표시하며, 목록이 길면 세로 스크롤로 확인합니다.

### 다운로드

- 마지막으로 검색을 실행한 조건의 결과만 내려받습니다.
- 제공받은 원본 파일과 동일한 컬럼 구성 · 순서 · 날짜 표기를 유지합니다.
- Excel에서 한글이 정상 표시되도록 UTF-8 BOM을 포함합니다.

## 주요 설계 결정

### 검색과 다운로드의 결과 일치

다운로드 요청은 목록 조회와 **동일한 서비스 메서드를 재사용**합니다.
조회 로직과 검증 로직이 한 곳에만 존재하므로, 화면에 표시된 결과와 내려받은 파일의 내용이
구조적으로 일치합니다.

또한 화면에서는 **입력 중인 검색 조건과 마지막으로 검색을 실행한 조건을 분리해 관리**합니다.
검색 후 입력값만 변경하고 다운로드를 실행하더라도, 현재 화면에 표시된 결과와 동일한
조건으로 파일이 생성됩니다.

### 목록 정렬 순서

정렬 기준에 대한 별도 요구사항이 없어 **제공받은 원본 데이터의 순서를 유지**했습니다.
CSV를 순서대로 적재하면서 부여된 식별자(`id`)를 기준으로 정렬합니다.

### 검색 조건 검증 위치

검증은 서비스 계층에서 수행합니다. 화면에서도 날짜 입력 컴포넌트로 형식 오류를 예방하지만,
API가 직접 호출되는 경우에 대비해 서버에서도 동일하게 검증합니다.
검증 실패는 전용 예외로 처리하고 `@RestControllerAdvice`에서 응답 형식을 통일했습니다.

### 검색 조건의 확장성

검색 조건은 단일 조건 객체(`EduHistorySearchVO`)로 전달하며, 동적 SQL에서 조건별로 분기합니다.
조건이 추가되는 경우 조건 객체의 필드와 동적 SQL 블록을 추가하는 것으로 대응할 수 있습니다.

### 테이블 컬럼 정의

화면의 목록 테이블은 컬럼 정의 배열을 기준으로 헤더와 본문을 함께 생성합니다.
컬럼 추가 · 변경 시 정의 배열만 수정하면 되며, 필드명이 타입과 연결되어 있어
응답 구조가 변경되면 컴파일 단계에서 확인할 수 있습니다.

## 제공 데이터 확인 사항

제공받은 CSV 파일을 적재하기 전에 데이터를 확인한 결과는 다음과 같습니다.
아래 두 항목은 **원본 데이터를 임의로 변경하지 않고 그대로 사용**했습니다.

### 중복 행

모든 항목이 동일한 행이 1건 존재합니다.
(`교육자 45 / 2024-07-08 / 2024-09-20 / 찾아가는 팀소통 / 인재개발원 / 수강`)

제거할 경우 화면설계서에 명시된 전체 건수(292건)와 일치하지 않게 되어 그대로 유지했습니다.

### 교육기관 표기 불일치

`한국생산성 본부`(9건)와 `한국생산성본부`(5건)가 함께 존재합니다.
동일한 기관으로 보이지만 검색 시 서로 다른 결과가 조회됩니다.

검색어 처리 단계에서 공백을 무시하도록 보정하는 방법도 있으나,
데이터 자체의 정합성 문제를 검색 로직으로 대체하는 것은 적절하지 않다고 판단해
원본 표기를 유지했습니다. 실제 업무에서는 데이터 정제 또는 기관 코드 관리로
해결할 사항으로 보이며, 요구사항에 따라 검색 시 공백을 무시하도록 변경하는 것도 가능합니다.

### 그 외

- 날짜 형식 오류, 누락된 값, 교육시작일이 교육종료일보다 늦은 행은 없습니다.
- 과정명에 쉼표가 포함된 항목이 있어, 읽기와 쓰기 모두 CSV 규격에 따라 처리했습니다.
